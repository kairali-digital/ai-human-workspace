# AI-Human Workspace v2.0.0

v2.0.0 makes the operating system company-neutral while binding Gate 0 to the exact
company or group, legal entity, operating unit, jurisdictions, purpose and user
relationship configured for each worker.

## What changed

- Separate public downloads now serve Kairali employees and reusable external users.
- Setup, troubleshooting, temporary suspension, resume, reversible uninstall, access
  revocation and visible ON/OFF/GONE verification are documented in one five-step path.
- Assignment intake and artifact upload stay intact even when a supplied document has
  150 entries. Actual item execution and separate external writes remain capped at 25.
- ACTIVE mode politely refuses only the conflicting part of a request and guides the
  user to the nearest compliant next step. That behavior is off when SUSPENDED.
- Gate 0 is generated from a confirmed local profile and stored separately from
  task-specific work locks. Historical material is a lead, never compliance proof.
- Completion now requires a ledger entry and detailed passing evidence with readback
  and undo information.
- Release/update integrity now rejects duplicate JSON keys, protected-state subtree
  targets, symbolic-link path redirection, stale release proofs and hostile ZIP members.

## Update classification

This release is `SETUP_MIGRATION_REQUIRED`. Existing v1.5.1 workers must configure and
validate their exact local Gate 0 profile at a safe checkpoint. v2.0.0 is deliberately
not eligible for automatic update application.

- `ai-human-workspace-2.0.0.zip`: installable source workspace.
- `kairali-company-rollout-2.0.0.zip`: Kairali reference pack and opt-in skills.
