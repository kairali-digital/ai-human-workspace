# AI-Human Workspace v2.2.0

v2.2.0 turns the universal homework into a durable personal-work assistant while also
shipping the held lifecycle-race correction. It is backward-compatible for configured
v2.0.0 and held v2.0.1 workers and preserves employee-owned state.

## Personal Work Memory + Daily Email EA

- The employee chooses one fixed daily local time and confirms the time zone.
- A read-only pilot precedes activation. The daily report presents priorities,
  follow-ups, useful reading, newsletter/filter proposals and concise replies marked
  `NOT SENT` in a clean notification format.
- The supervised memory baseline stores only concise sourced work context. Every item
  is `CONFIRMED` or `OBSERVED — VERIFY`, dated and reviewable.
- Employees can show, correct, exclude, forget or refresh memory. Full mailbox copies,
  hidden profiling, sensitive inference, silent unsubscribe, sends and silent
  permanent-filter changes remain prohibited.

## Drive Master Index

- `DRIVE-INDEX.jsonl` is the normalized AI-readable file of record, deduplicated by
  stable item ID.
- One human register is generated from that exact data: an explicitly approved Google
  Sheet or otherwise `DRIVE-REGISTER.csv`.
- JSONL, human register, summary and cursor share one generation ID. Completion fails
  closed unless both registers reopen and all counts reconcile.
- `TEST 25` remains a labelled learning sample. `FULL DRIVE INDEX` covers every
  connector-supported scope in checkpointed batches no larger than 25.
- After the first full proof, the worker offers an employee-confirmed weekly refresh.
  It never invents a time or silently activates a schedule, never deletes a record
  merely because it is temporarily invisible, and never advances a cursor after a
  failed readback.

## Optional LinkedIn learning

LinkedIn remains human-accessed and human-sent. From manually supplied text and
employee-confirmed outcomes, the worker may save only concise explicitly approved tone
or work-context rows. Each can be corrected or forgotten; full conversations,
sensitive traits and private inference are excluded.

## Lifecycle safety correction

Task start and completion now acquire the exclusive worker lease before reading,
checking or rendering controlled state. Forced concurrent start and completion tests
require exactly one winner and one clean refusal while preserving the winner's state,
receipt and final validator result.

## Install or recover

- Configured v2.0.0 or held v2.0.1 workers use the normal read-only version check and
  approve v2.2.0 only at a safe checkpoint.
- The unpublished v2.0.2 candidate is superseded by this combined release.
- Pre-v2 workers still complete the guided exact-scope Gate 0 migration first.
- New users choose exactly one edition. Kairali staff use the Kairali Employee Edition;
  everyone else uses the company-neutral Reusable Edition.

Automatic update eligibility remains off. A portal label or download is not proof
that an individual worker was updated; its version, preservation receipt and validator
result remain the proof.
