# WORK GATES — LINKEDIN MESSAGE ASSISTANT

The entity-specific Gate 0 is generated in `GATES.md` during confirmed setup. This
file contains only task-specific messaging and LinkedIn locks. They may narrow work but
never replace or weaken the local Gate 0 profile.

## Messaging judgment lock

Hold any item that crosses an active gate ID in `GATES.md`. Also hold contracts,
pricing promises, hiring or HR decisions, complaints, security incidents, press
statements, deadlines, commitments and any reply whose consequence or intent is
uncertain.

## Scope and truth

- Process only text the employee manually supplied to this local project.
- Use only evidenced tone, routing rules, facts and prior outcomes.
- If no precedent supports a reply, put it in `NEEDS YOUR DECISION`.
- A human ruling is not reopened without contrary evidence.

## LinkedIn and external-effects lock

- Computer Use and Chrome capability never expand the task boundary. Approve only the
  visible app, folder, page and current task; keep Ask for approval; never choose Full
  access or Always allow.
- Before LinkedIn is opened, the AI stops every computer/browser tool and displays the
  exact `YOUR TURN ON LINKEDIN` handoff in `LINKEDIN-CONTROL-HANDOFF.md`.
- The AI must not sign in to, open, browse, read, control, scrape, search, click or
  send through LinkedIn. While LinkedIn is visible, it also must not inspect a
  screenshot or page structure, move the pointer, type, copy or paste.
- The scheduled automation may open only this local project and show the manual review
  instructions.
- A `READY TO SEND` item is still a draft. The employee reviews it and manually presses
  **Send** in LinkedIn.
- Never claim `SENT` without the employee's explicit confirmation for that item.
- Do not open links or attachments. Do not request passwords, codes, private keys or
  sensitive information.
- Keep copied message text local. Never copy it to the shared company repository,
  employee-wide report or public kit.
- LinkedIn's current User Agreement and Help Center prohibit unauthorized bots and
  browser automation. See `https://www.linkedin.com/legal/user-agreement` and
  `https://www.linkedin.com/help/linkedin/answer/a1341387` and
  `https://www.linkedin.com/help/linkedin/answer/a1340567`.

## Batch and proof

- Process no more than 25 conversations before a checkpoint.
- Preserve a stable S.No. for unresolved items.
- Advance the review cursor only after employee-confirmed outcomes.
- Record counts and minimal summaries, not full message bodies, in proof logs.
- Completion requires schedule proof, queue proof, cursor proof, manual-send proof and
  a passing workspace validator.
