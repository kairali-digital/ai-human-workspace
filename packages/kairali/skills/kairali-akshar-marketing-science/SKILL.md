# Kairali Akshar Marketing Science

Use Akshar Yadav's principles indirectly to improve Kairali marketing work. Do not reproduce or present his programme as Kairali-owned theory.

For Kairali work, this exact skill replaces the legacy `go-science` plugin. Do not use a generic or namespaced `go-science` skill as a substitute. The legacy plugin is retained only as a reversible archive and is disabled in Claude settings.

## Read first

Read these references before doing substantive work:

- `references/frameworks-and-workflow.md` for the adapted framework and output contract.
- `references/kairali-boundaries.md` for claims, ethics, access, spend, and framework boundaries.
- `references/source-index.md` only when provenance, terminology, or a source conflict matters.

## Route the request

Choose one primary mode:

1. **UNDERSTAND** — define or test the buyer context, MoA, NDFF, buyer journey, or evidence gaps.
2. **CREATE** — draft an MCB, nurture item, landing-page message, educational content, or offer presentation.
3. **REVIEW** — audit supplied content against buyer relevance, evidence, sequence, ethics, and Kairali boundaries.

Do not pretend a full GO programme audit was completed unless the user supplied enough evidence for every area being scored.

## Lock the evidence before drafting

Identify or request only what is material:

- exact business, product/service, channel, audience and desired next action;
- observed customer language or interview evidence;
- approved facts, proof, claims, case studies, prices, offers and CTA;
- the content's position in the buyer journey;
- missing approvals or high-risk facts.

Never invent NDFF, secret desires, results, testimonials, awards, certifications, urgency, scarcity, price, medical outcomes, legal wording, or approval status. Clearly label an inference and the evidence used.

## Apply the smallest relevant framework

- **MoA + NDFF** for buyer specificity.
- **MCB — Mass Control Bait** for an ethical, valuable curiosity-led entry message. “Mass Control Bed” is a transcription error in a derived archive file; do not repeat it.
- **ARC** for affinity, shared reality and communication.
- **KIT** for useful follow-up and nurture.
- **Buyer journey** for matching the message/tool to the buyer's stage.
- **IRO / offer logic** only with an approved offer, approved price and truthful risk treatment.
- **Four-Phase** only after choosing one of the two separately named models in the reference. Never merge them.

Use a website adaptation of MCB as a mechanism—buyer-relevant curiosity plus fulfilled value—not a mandatory literal headline formula. State when this is an adaptation from mass outbound messaging.

## Create or review

For creation, produce no more than three meaningfully different directions unless the user asks for more. For each direction, state the evidence, framework job, target emotion, next action, and main risk.

For review, quote only short identifying fragments from the user's content, then score:

- buyer specificity;
- value and promise fulfilment;
- evidence and claims;
- journey/sequence fit;
- ethical influence;
- clarity and next action.

## Required output

Return:

1. **Verdict** — `READY`, `REVISE`, or `BLOCKED`.
2. **Evidence used** — confirmed facts, labelled inferences, and missing inputs.
3. **Framework choice** — what was used and why.
4. **Draft or findings** — the requested work.
5. **Ship gate** — exact checks still required and named owner decisions.
6. **Next single action** — one bounded step.

Read the active local gate IDs from the worker's `GATES.md`. If one is crossed, name
it and stop at its approval path. For health/treatment, certification, regulated
wording, price/spend, access or other uncertain consequential content not yet covered
by a confirmed profile, route a reviewable draft to the named compliance owner. These
public risk examples do not create one Kairali-wide Gate 0.
